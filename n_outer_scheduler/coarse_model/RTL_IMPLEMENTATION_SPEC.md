# Future RTL implementation contract

No RTL has been modified. This document specifies the smallest implementation
compatible with the validated Python semantics.

## Required state

The candidate scorer requires:

- two cluster completion timestamps;
- two boundary-prefetch release timestamps;
- two DMA-lane free timestamps;
- two predicted LPT assignment accumulators;
- current expert ID, real token start/count, and optional second slice;
- Gate/Up and Down shape codes;
- Gate/Up and Down DMA masks (`01=IDMA`, `10=XDMA`, `11=BOTH`);
- optional resource-stall and pipeline-stall counters for debug/calibration.

The scheduler does not store block descriptors. Phase block count and weight
bytes are configuration constants. Ping/pong selection is the fixed block
index low bit inside the Bingo worker.

## Assignment front end

Experts are consumed in non-increasing service cost. The service cost can be a
small ROM indexed by real token count; it is the cold single-lane N-outer task
duration produced by the Python model. The next expert is assigned to the
cluster with the smaller predicted LPT accumulator, then its ROM cost is added.

This operation can be performed online as a sorted window is refilled. It does
not require an offline future expansion. To reproduce a full-distribution LPT
order exactly, the producer must supply experts in non-increasing cost. A
top-only refill protocol is sufficient for that property; a top+bottom window
is needed only if later candidate ablation demonstrates value from cold-tail
pair selection.

## Candidate bank

For the two current cluster heads, generate at most two joint modes:

1. parallel singles: C0=IDMA, C1=XDMA;
2. all-BOTH, only when every task and both phases legally support BOTH.

Locally dominated modes are suppressed by `L_single <= C`. Gate/Up and Down
legality are evaluated independently. One-sided and phase-mixed BOTH modes are
not generated by the deployable bank. K4/K8 remain software ablations only.

Each DMA mode uses one deterministic `binding_chain` service order: prioritize
the task with more BOTH-bound phases, then the larger total resident-block
compute window, then cluster ID; run that task's four phase operations before
the peer's. The 18-order Python bank is retained only as a calibration upper
bound. It is not multiplied into the RTL candidate count. The frozen bank
therefore needs at most two actual timespan evaluations. Across the final 65
cases, `binding_chain` is equal to the best-of-18 macro policy after executable
replay in 63 cases, better in 2, and worse in 0.

SPLIT is not part of the frozen RTL-oriented policy. The current top-1 SPLIT
implementation selects its cut after comparing complete histories and is kept
only as an offline upper-bound ablation. A future deployable SPLIT proposal must
define a bounded current-state cut rule and keep the no-SPLIT candidate.

## Timespan engine

The exact Python macro operator uses a ready-only fixed-block recurrence. The
direct sequential RTL mapping uses one reused datapath and a small FSM:

1. derive the next legal load release from phase/block counters;
2. compare its selected lane mask with lane-free timestamps;
3. start only currently ready requests;
4. add the configured load duration to the selected lane timestamp(s);
5. compute block start as the maximum of load completion and prior compute
   completion;
6. add the shape-dependent compute duration;
7. repeat for the fixed Gate/Up and Down block counts;
8. return cluster ends, lane ends, and stalls.

The datapath consists of adders, maximum/comparison logic, small counters, and
mode/configuration ROMs. A candidate does not require a separate FSM or a
separate register bank. Candidate count increases evaluation cycles, not the
number of persistent schedule states. The frozen implementation reuses the
same engine at most twice.

The fixed recurrence is the selected implementation, not a temporary
block-level scheduler. A single aggregate phase interval cannot simultaneously
preserve ping/pong release, ready-only holes, and contention between a BOTH
stream and a single-lane stream. Replacing the recurrence would therefore be
an unvalidated approximation. The recurrence has fixed trip counts and stores
no block descriptors; it is reused sequentially for both modes. Block IDs remain
internal counters and never enter candidate generation or the macro result.

## Score and selection

For every candidate:

```text
primary   = max(C0_end, C1_end, iDMA_free, xDMA_free)
secondary = max(C0_end, C1_end)
mode_id   = 0 for fixed lanes, 1 for all-BOTH
```

Select lexicographically minimum
`(primary, secondary, mode_id, stall, signature)`. Placing mode ID before stall
is intentional: an equal primary/secondary score falls back to the
no-contention fixed-lane plan. A local BOTH-first tie rule regresses 31 of 65
cases. No multiplication, division, trained residual, or future lookahead is
required.

## Bingo macro record

One selected expert slice produces one record containing:

- action sequence and action kind;
- cluster and cluster-local sequence index;
- expert ID;
- real token start and count;
- Gate/Up shape and DMA mask;
- Down shape and DMA mask;
- four finite service-priority ranks. With `binding_chain`, these ranks are
  derivable and may be replaced by one fixed rule identifier in the physical
  ABI.

The fixed Bingo worker expands the record as expert -> Gate/Up blocks -> Down
blocks, alternates two weight buffers, and uses the real token range for all
resident-block compute iterations. Physical Bingo slot IDs are deliberately
not fixed by the software model.

`bingo_task_abi.py` defines the next lowering boundary. It expands this macro
record into dependency-only LOAD_WEIGHT and COMPUTE_BLOCK arguments for a
fixed task graph. DMA-lane predecessors, prior compute, and ping/pong release
are explicit dependencies; absolute model timestamps are not ABI fields. See
`BINGO_ABI_MAPPING.md` for the read-only audit of the current M-outer ABI and
the fields that require a separate N-outer C implementation.

## Required sign-off checks

RTL implementation must pass all of the following against identical macro
records:

1. macro result equals the Python timespan engine or is conservatively later;
2. independent task replay has no DMA-lane overlap;
3. load `i` does not overwrite the buffer used by compute `i-2`;
4. every real token is covered exactly once, including SPLIT;
5. phase and expert order match the macro records;
6. first-block traffic is charged or demonstrably supplied by the predecessor;
7. the 65-case policy remains no worse than fixed-lane LPT on every case and
   preserves the frozen aggregate ratios;
8. all result source hashes match the RTL-reference Python sources used for
   sign-off.
